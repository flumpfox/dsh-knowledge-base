# База знаний

Собирает локальные базы знаний для агента из внешних источников и даёт ему четыре инструмента над ними. Источников может быть несколько, у каждого своя база. Сейчас поддерживается Confluence Server / Data Center — по REST API или из zip-архива HTML-экспорта на диске; в планах Jira, Obsidian и другие источники. Корпус (markdown-статьи и `kb.sqlite`) создаёт `kb.py`; плагин читает его и запускает импорт.

## Что получает агент

| Инструмент | Назначение |
|---|---|
| `kb_search` | полнотекстовый поиск по заголовкам и тексту, с ранжированием и фрагментом |
| `kb_read` | статья целиком, по id страницы или фрагменту заголовка |
| `kb_review` | очередь статей, которым пора на перепроверку |
| `kb_status` | число статей, пространства, статусы, дата последнего импорта, отставание индекса |

Каждый результат несёт `updated` (дата изменения самой страницы), `status`
(`current` / `legacy` / `deprecated`) и вычисленные флаги вроде `review-due` или `8m old`.
Свежесть едет вместе с фактом: агент видит её в момент использования.
`kb_search` и `kb_read` печатают `file=` **абсолютным** путём. Относительную ссылку приложение
разрешает от рабочего каталога сессии, а база лежит вне его, поэтому боковая панель ответила бы
«файл не найден»; абсолютный путь открывает статью там, и описания инструментов со скиллом
требуют цитировать его как есть, ссылкой markdown. Оба инструмента печатают и `source=` — адрес
первоисточника в Confluence, собранный из базового URL источника и id страницы (у файлового
источника его нет). Куда открывать ссылки, решает настройка DSH «Настройки → Общие → Открыть
ссылки на чат в»: боковая панель в приложении или браузер по умолчанию, — так что первоисточник
открывается одним щелчком там, где удобно читателю.

## Настройки → База знаний

Раздел стоит после «Плагинов». Источник выбирается один из двух:

- **Подключение к серверу** — базовый URL и один из двух способов аутентификации:
  - **Personal Access Token** (`Authorization: Bearer`) — для Confluence Data Center, где
    токены включены.
  - **Пользователь и пароль** (HTTP Basic) — этот способ принимает любой Confluence Server.

  «Проверить подключение» подписывает запрос, спрашивает у сервера, кто мы, и затем
  показывает пространства, доступные этой учётной записи. Если сервер отвечает как анонимный
  пользователь, страница говорит, что учётные данные не приняты, вместо пустого списка:
  Confluence Server без поддержки токенов полностью игнорирует заголовок `Authorization:
  Bearer` и отвечает `200` без пространств, что иначе выглядело бы как пустая вики. Оба
  секрета лежат в хранилище секретов DSH и на страницу не возвращаются; в `kb.py` токен и
  пароль попадают через переменные окружения, а не через командную строку.
- **Файл экспорта** — полный путь к zip из Confluence → Пространство → Экспорт → HTML.
  «Проверить файл» проверяет его через `kb.py inspect`: файл должен существовать, быть
  непустым, быть настоящим zip и содержать HTML-страницы. Страница показывает размер, число
  страниц-кандидатов и пространства из `index.html` самого архива, поэтому выбор пространств
  работает одинаково в обоих режимах. Токен здесь не нужен и не запрашивается.

У списка пространств есть фильтр по ключу и названию, «выбрать все отфильтрованные»,
«снять выбор», счётчик выбранных, и выбор сохраняется. «Все пространства, включая новые»
импортирует весь сервер; список остаётся рабочим, а пояснение говорит, что на импорт он
больше не влияет.

Расписание хранит два интервала: инкрементальный проход (только страницы, изменённые с
прошлого успеха) и полный (он же замечает удаления). Host запускает их по своему часовому
таймеру, **пока запущено приложение DSH**: открытый чат для этого не нужен, а закрытое
приложение импорт не выполняет. В файловом режиме каждый запуск переимпортирует тот
же путь — это удобно, если архив кладёт туда другой инструмент.

## Перенос базы между машинами

Три действия работают с самой базой, ниже настроек источника:

- **Экспортировать базу** спрашивает, куда сохранять: папка — «Обзор…» открывает системный выбор
  папки, а введённый вручную абсолютный путь тоже принимается — и имя файла, при необходимости с
  дописанным `.zip`. Существующий файл не перезаписывается молча: страница спрашивает
  «Заменить» или «Отменить», и только «Заменить» разрешает перезапись — упаковка пишет временный
  файл и переименовывает его, поэтому неудачный запуск оставляет старый архив целым. Упаковка идёт в фоне: страница
  показывает, сколько байт сделано из скольких, полосу и процент, а «Отменить упаковку»
  останавливает процесс и удаляет частичный файл. По завершении видно полный путь, число статей и
  размер, а «Открыть папку» показывает файл в системном файловом менеджере (в Windows — проводник с
  выделенным архивом, в macOS — Finder, в Linux — папка с файлом). Открывается только путь
  завершённого экспорта: маршрут не принимает путь со страницы, а если файл уже убрали, страница
  скажет об этом. В архив попадает весь корпус — статьи, `MANIFEST.jsonl`, `kb.sqlite`, вложения — и
  `knowledge-base.json` с именем источника, его видом, **базовым URL**, пространствами,
  расписанием и языком. Учётных данных в архиве нет: они лежат в хранилище секретов DSH, а не в
  базе. `raw/` (распакованный экспорт, вход импорта) и старый `connection.json` не включаются —
  они создаются заново при необходимости.
- **Импортировать базу** восстанавливает такой архив новым источником (`kb.py unpack`) с новым
  id и своим каталогом. Из Confluence ничего не загружается, поэтому это работает на машине без
  доступа к серверу; учётные данные нужно ввести там. Последующий импорт с того же базового URL
  работает как обычно: движок сравнивает с восстановленным манифестом и продолжает с состояния,
  оставленного другой машиной.
- **Удалить файлы базы** убирает статьи, индекс и вложения одного источника, сохраняя его
  настройки и учётные данные; базовый URL при этом разблокируется. Удаление источника убирает и
  источник, и файлы, и работает даже для последнего источника: страница показывает пустое
  состояние с кнопками «добавить источник» и «импортировать базу».

Базовый URL фиксируется, как только источник что-то загрузил с него: статьи хранят этот URL в
заголовке, и переназначение источника на другой сервер заставило бы локальный корпус ссылаться
на сервер, который его не отдавал. Поле становится только для чтения с подсказкой, а сервер
отказывает в смене URL кодом `error.baseUrlLocked`. Чтобы подключиться к другому серверу, очистите
базу или создайте новый источник. Источник, восстановленный из архива, зафиксирован навсегда:
его URL — часть архива.

## Прогресс и остановка

`kb.py --progress` печатает в stderr строки `PROGRESS <done>/<total> <space>`, по одной на
страницу; Host их разбирает и отдаёт из `GET /x-knowledge-base/sources/<id>/job` (устаревший `GET …/job` отвечает для источника по умолчанию). Страница показывает,
сколько страниц обработано из скольких, какое пространство идёт, сколько прошло времени, и
полосу прогресса. «Остановить» посылает SIGTERM процессу движка; запуск завершается
состоянием `cancelled`, а не выдаётся за ошибку.

Знаменатель берётся из `totalSize` CQL-поиска страниц. Confluence Server не отдаёт это поле в
обычном листинге содержимого, поэтому полный импорт, считающий только через
`/rest/api/content`, показывал бы обработанные страницы без общего числа. Движок сначала
спрашивает поисковый эндпоинт и держит обычный листинг лишь запасным вариантом — для установок,
где поиск ограничен. Если счётчик не отдаёт ни один эндпоинт, страница показывает число
обработанных страниц без процента, а не выдумывает знаменатель.

## Каждый запуск становится записью в задачах автоматизации

Когда импорт завершается — успехом, ошибкой или остановкой — плагин записывает итог на
страницу «Задачи автоматизации»: источник, адрес, режим, время начала, длительность,
добавлено / изменено / перенесено в tombstone / пропущено, результат и ошибку, если она была.
Запись одна и обновляется при следующих запусках; создаётся она как одноразовое срабатывание
далеко в будущем и сразу ставится на паузу, поэтому никогда не доставляет сообщение в чат.
В самом отчёте сказано, что это запись отчёта, а не напоминание: импорт — собственная работа
плагина по расписанию, а не задача, ждущая срабатывания.

Если в профиле нет службы задач автоматизации или она отклонила запись, страница говорит об
этом прямо, и в выводе движка есть та же строка. Ничто не делает вид, что запись создана.

## Несколько источников — по базе на каждый

Источник — это одна вики и одна база знаний: свой каталог, свой `kb.sqlite`, манифест,
расписание, задача импорта и запись в задачах автоматизации. Импорт трогает только свою базу,
поэтому вторая вики никогда не пометит статьи первой как tombstone.

Один источник — **по умолчанию**: сессия без другой привязки ищет по нему. **Рабочая область**
может вместо этого привязать упорядоченный набор источников, и тогда каждый вызов инструмента
из сессии в этой области читает ровно их, в этом порядке. `kb_status` перечисляет источники,
говорит, какой из них по умолчанию и до каких дотянулся вызывающий.

| Инструмент | Когда источников несколько |
|---|---|
| `kb_search` | ищет по всем источникам набора и перемежает их ранжирования; в каждом попадании есть `source` и `sourceName` |
| `kb_read` | находит статью в первом источнике набора, где она есть |
| `kb_review` | одна очередь по набору, каждый пункт помечен источником |
| `kb_status` | по блоку на источник: статьи, пространства, статусы, дата импорта, отставание индекса |

Заголовок карточки вызова инструмента — единственная её часть, которую читает человек, —
показывается на языке, выбранном для источника, к которому относится вызов (русский или
английский): на том же языке, что и страница настроек, и отчёты об импорте. Текст результата
остаётся английским, как у любого другого инструмента: это данные для модели, и их перевод
изменил бы то, что получает модель.

Параметр `source` у трёх читающих инструментов ограничивает вызов одним идентификатором
источника.

Миграция молчаливая: прежнее единственное подключение (старый `connection.json`) становится
источником по умолчанию и сохраняет свой каталог базы, так что статьи, манифест и индекс
остаются на месте.

## Требования

- Каталог базы на каждый источник (`~/.dsh/kb/<id>`; `$KB_HOME` задаёт базу по умолчанию для
  движка), каждый со своим `kb.sqlite` и файлами
  статей. Создаётся через `kb.py import --zip …` или `kb.py fetch --url …`; страница тоже умеет
  это делать.
- Python на машине (используется встроенный рантайм DSH, если он есть) и движок `kb.py` из
  репозитория этого пакета либо установленный скилл `knowledge-base`.
- Встроенный в Node `node:sqlite` с FTS5 — в этой сборке DSH он есть.

## Ограничения, честно

- Заголовки вложений не всегда годятся в имена файлов: `image 21:0:24.png` допустим в Confluence и запрещён в Windows. Каждый компонент пути приводится к переносимому виду (запрещённые символы → `_`, хвостовые точки убираются, служебным именам вроде CON добавляется префикс) и при распаковке архива, и при ссылке из статьи, поэтому ссылка и файл на диске совпадают. Два разных заголовка, дающих после замены одинаковое имя в пределах одной страницы, столкнутся.
- Плагину нужен построитель инструментов хоста (`@deepseek-ai/dsh-tools`). Бандл, подключённый из рабочего каталога, берёт его из запущенного приложения; если недоступна ни одна копия, страница настроек всё равно открывается, а инструменты `kb_*` не появляются — причина пишется в лог Host.
- Учётные данные лежат в хранилище секретов DSH: одна запись на источник с ключом `knowledge-base-tools/<id>`. Хранилище принимает только `<scope>/<id>`; ключ с лишним сегментом не даёт приложению загрузить файл секретов при старте. Прежняя версия писала ключи из трёх сегментов (`confluence-kb/<id>/basic`) и могла уронить приложение; если это случилось, удалите записи `confluence-kb/…` из `~/.dsh/.credentials.yaml` и сохраните учётные данные заново. Id источника, который не годится в сегмент ключа (например, начинается с цифры), заменяется стабильным хеш-слотом `s-<16 hex>`.
- Онлайн-доступа к Confluence нет. Страница, изменённая после последнего импорта, не видна до
  следующего импорта, а `kb_status` сообщает об устаревшем индексе, но не чинит его.
- Поиск лексический (префиксный FTS5), не семантический: для синонимов нужен второй запрос.
- Вложения — файлы на диске, а не индексированный текст; `kb_read` возвращает только тело.
- Остановленный импорт оставляет уже записанные страницы; отката нет.
- Остановка — один SIGTERM движку; плагин не ждёт подтверждения, что процесс завершился.
- Импорт идёт по одному на Host; второй запрос во время работы отклоняется.
- Список пространств — плоский прокручиваемый список: без виртуализации, страница держит его
  в памяти.
- Один `id` — один файл. Импорт удаляет устаревшего двойника с тем же `id` (в сводке это
  строка `duplicates`), а индекс держит одну строку на `id` и предупреждает об остатках вместо
  падения.
- Страницы с пустым телом пропускаются («no content»): они остаются в вики, но не в базе.
- Отчёт о запуске называет источник и его базу; запись в задачах автоматизации — своя на каждый
  источник.
- Экспортированный архив не шифруется: в нём тексты статей и вложения. Учётных данных там нет,
  но обращаться с ним стоит как с корпусом.
- Базовый URL импортированной базы окончателен; переезд на другой сервер — это импорт архива
  новым источником, а не правка старого.
