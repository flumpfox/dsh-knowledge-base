# Плагин dsh-knowledge-base

Английский оригинал: [README.md](README.md).

Бандл DSH, который собирает локальные базы знаний для агента: четыре инструмента над корпусом,
который создаёт `kb.py`, плюс раздел «Настройки → База знаний», где настраивается источник,
выполняется импорт пространств, показывается живой прогресс, экспортируются и импортируются базы,
а каждый запуск записывается на страницу задач автоматизации. Сейчас поддерживается Confluence
Server / Data Center (по REST API или из HTML-экспорта); Jira, Obsidian и другие источники — в
планах.

| Половина | Файл | Ответственность |
|---|---|---|
| Host | `index.js` | регистрирует инструменты и маршруты настроек |
| Host | `server.js` | `/x-knowledge-base/*`: реестр источников, состояние, проверка, пространства, импорт, задача, отмена, учётные данные, очистка, экспорт, импорт базы, выбор папки, локаль |
| Host | `lib/registry.js` | чистая модель реестра: источники, умолчание, наборы рабочих областей, слияние результатов |
| Host | `lib/core.js` | чистые помощники: прогресс, сводка, URL, расписание, пути (без I/O) |
| Client | `client.js` | раздел настроек: список источников, форма создания, редактор, наборы рабочих областей |
| Тексты | `locale/{en,ru}.json` | весь пользовательский текст, включая отчёт задачи автоматизации |

## Маршруты

Все маршруты живут под `/x-knowledge-base` и отвечают JSON.

| Маршрут | Назначение |
|---|---|
| `GET/POST /sources` | список реестра; создание источника с именем и id |
| `POST /default`, `POST /workspaces` | выбрать основной источник; привязать набор рабочей области |
| `GET/POST /sources/<id>` | прочитать состояние; сохранить настройки источника |
| `POST /sources/<id>/{delete,clear}` | удалить источник; удалить только файлы его базы |
| `POST /sources/<id>/{test,spaces}` | проверить подключение; список пространств |
| `POST /sources/<id>/{import,cancel}` | запустить импорт; остановить его |
| `GET /sources/<id>/{job,export}`, `GET /sources/<id>/export/job` | прогресс импорта; план и прогресс экспорта |
| `POST /sources/<id>/export`, `POST …/export/{cancel,reveal}` | запустить упаковку, отменить её, показать архив |
| `POST /sources/<id>/{token,basic}` | сохранить или удалить учётные данные |
| `POST /import-base`, `POST /pick-folder` | восстановить переносимую базу; открыть системный выбор папки |
| `GET /locale/<lang>.json` | словари, которые использует страница |

## Установка

Установите `dsh-knowledge-base-<версия>.tgz` со страницы GitHub Releases (DSH → Plugins → Add
plugin или `plugin_manager install_bundle <путь>`), положите `skill.zip` в
`%USERPROFILE%\.dsh\skills\knowledge-base\`, затем перезапустите приложение.

Для разработки подключите `plugin/` в профиль ссылкой (`link:`-зависимость плюс запись в списке
бандлов) и переключайте бандл через `set_bundle`; связанный Host-модуль перезагружается без
перезапуска, клиентские изменения требуют обновления страницы. `npm test` прогоняет набор тестов
плагина (51 кейс) через инструменты репозитория, которые сами находят Python для интеграционных
тестов.

Связанный бандл разрешает импорты из рабочего каталога, а не из профиля, поэтому
`@deepseek-ai/dsh-tools` грузится лениво: сначала обычным импортом, затем из копии внутри
`app.asar` запущенного приложения. Без этого запасного пути бандл падал с
`ERR_MODULE_NOT_FOUND`, и страница настроек не поднималась. `tests/boot.test.js` закрепляет
урезанное поведение: нет построителя инструментов — нет `kb_*` и предупреждение в лог, но
плагин жив.

Поведение, требования и ограничения — в [docs/DETAIL.ru.md](docs/DETAIL.ru.md) (по-английски:
[DETAIL.md](docs/DETAIL.md)).
