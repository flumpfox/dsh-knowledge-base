# Как участвовать

Спасибо, что нашли время. Это небольшой проект с несколькими правилами, которые держат его
предсказуемым.

## Перед началом

- Прочитайте [docs/DEVELOPMENT.ru.md](docs/DEVELOPMENT.ru.md): окружение, структура, команды тестов.
- Для ошибки откройте issue по шаблону: версия DSH, версия Confluence, режим аутентификации,
  вывод `kb_status` и шаги. Никогда не вставляйте токены и пароли.
- Для крупного изменения сначала откройте issue, чтобы договориться о направлении до кода.

## Pull request

- Держите PR сфокусированным: одна проблема, одно изменение, с коротким описанием «почему».
- Перед пушем выполните `npm test` и `npm run check-secrets`; оба должны быть зелёными.
- Пользовательский текст — только в `plugin/locale/{en,ru}.json`, никогда в коде.
- Документация двуязычная: меняйте `X.md` и `X.ru.md` вместе.
- Изменение поведения требует теста; изменение CLI требует обновления тестов движка.
- Никаких секретов, внутренних хостов и личных путей в коде, тестах, документации и фикстурах.

## Стиль

- JavaScript — обычный ESM без runtime-зависимостей; Python — только стандартная библиотека.
- Комментарии объясняют, *почему* что-то сделано, а не что делает следующая строка.
- Сообщения коммитов называют проблему и решение, а не только затронутые файлы.

## Поведение

Будьте вежливы и предполагайте добрые намерения. Оскорбления, личные атаки и дискриминационные
формулировки не приветствуются и будут удалены; мейнтейнеры могут блокировать аккаунты, которые
продолжают.
