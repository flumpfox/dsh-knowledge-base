# kb.py — движок

Английский оригинал: [README.md](README.md).

Confluence → база знаний в markdown, с провенансом. Это CLI-половина: плагин DSH
(`../plugin`) управляет ею, скилл (`../skill`) оборачивает её для `~/.dsh/skills`, и обе
работают с одной и той же раскладкой корпуса.

Суть не в «конвертировать HTML в markdown». Суть в том, что содержимое вики незаметно устаревает,
поэтому каждая статья несёт, откуда она пришла, когда изменилась и актуальна ли ещё.

```
engine/
  kb.py                  CLI (только стандартная библиотека, без зависимостей)
  tests/run_tests.py     17 сквозных кейсов
  tests/make_fixture.py  синтетические экспорты (в т.ч. вложение с ':' и дубликаты id)
  tests/mock_confluence.py  мок REST Confluence 8.x (Bearer/Basic, пагинация, CQL, задержка)
```

## Команды

```
kb.py [--version]
kb.py [--kb DIR] import  --zip FILE [--base-url URL] [--spaces KEYS] [--progress] [--dry-run]
kb.py [--kb DIR] inspect --zip FILE [--json]
kb.py [--kb DIR] fetch   --url URL (--token T | --user U --password P) [--spaces KEYS]
                         [--space-type global|personal|all] [--since YYYY-MM-DD]
                         [--no-attachments] [--save-zip FILE] [--list-spaces]
                         [--progress] [--insecure] [--dry-run]
kb.py [--kb DIR] index | search "terms" [-n N] [--space S] [--status S] | get ID
                 | audit [--months N] [--json] | stats
                 | pack --out FILE [--meta FILE] [--progress] [--json]
                 | unpack --archive FILE [--check] [--json]
```

`--kb` по умолчанию берётся из `$KB_HOME`; иначе движок читает `$KB_DIR` (или `~/.dsh/kb`) `knowledge-sources.json` и берёт каталог источника по умолчанию; если нет ни того, ни другого — сообщает, что база не настроена. `--version` печатает версию движка.

- **`import`** — это diff, а не перезапись: неизменённые тела остаются побайтово прежними,
  изменённые перегенерируются, исчезнувшие из архива страницы становятся tombstone-записями.
  `--spaces` сужает мультипространственный архив, но страницы остальных пространств всё равно
  считаются присутствующими, поэтому сужение никогда не превращает их в tombstone.
- **`inspect`** проверяет архив, не трогая базу: файл должен существовать, быть непустым, быть
  настоящим zip и содержать HTML-страницы. Он сообщает размер, число файлов-страниц и
  пространства, прочитанные из каждого `index.html`; при ошибках отдаёт стабильные коды
  (`file-missing`, `file-empty`, `file-not-zip`, `file-no-pages`, `file-unreadable`).
- **`fetch`** перечисляет все видимые пространства (`/rest/api/space`), обходит страницы каждого
  пространства (`/rest/api/content` с `expand=body.view,version,space` или CQL-поиск
  `lastmodified >` при `--since`), скачивает вложения, пишет zip в формате экспорта в `raw/` и
  прогоняет по нему обычный импорт — поэтому импорт через API и импорт файла в одну и ту же базу
  сравниваются друг с другом. `body.view` — это отрендеренный самим Confluence HTML, так что
  обработка макросов совпадает с zip-путём. Запросы идут последовательно, с экспоненциальной
  паузой при 429/5xx.
- **`--progress`** (для import и fetch) печатает в stderr строки `PROGRESS <done>/<total> <space>`,
  по одной на страницу; `total` — это число страниц в архиве или сумма `totalSize` CQL-поиска
  страниц. Confluence Server не отдаёт `totalSize` в обычном листинге `/rest/api/content`,
  поэтому `fetch` спрашивает счётчик у `/rest/api/content/search`, а обычный листинг держит
  только запасным вариантом. Страница настроек DSH разбирает ровно этот формат.

- **`pack`** пишет переносимый архив одной базы: статьи, `MANIFEST.jsonl`, `kb.sqlite`,
  вложения и `knowledge-base.json` с `"format": "dsh-knowledge-base-base"` и публичными
  метаданными источника из `--meta` (имя, базовый URL, пространства; никогда — креды).
  `raw/` и старый `connection.json` в архив не попадают. `--progress` печатает в stderr
  строки `PACK <done>/<total>` в байтах.
- **`unpack`** проверяет и восстанавливает такой архив; `--check` проверяет, ничего не записывая.
  Архивы со старым маркером `confluence-kb.json` / `dsh-confluence-kb-base` по-прежнему
  принимаются; распаковка отвергает обход путей, чужой формат и отсутствие маркера.

## Раскладка базы

```
<KB>/
  INDEX.md                     сгенерированное оглавление по пространствам
  MANIFEST.jsonl               строка на страницу: id, hash, даты, сигналы
  kb.sqlite                    индекс FTS5 (производный: можно удалять, пересобирается)
  <space>/<title-slug>--<id>.md
  attachments/<pageId>/...
  raw/<stamp>-<ziphash>/       распакованный экспорт, из которого пришёл импорт
```

Frontmatter статьи:

```yaml
id: 101                     # id страницы Confluence (стабилен при переименованиях)
title: Настройка Patroni в двух ЦОД
space: DBA
source_url: https://confluence.../pages/viewpage.action?pageId=101
source_updated: 2025-03-14  # дата, напечатанная внутри страницы, либо unknown
ingested: 2026-11-18        # когда этот экспорт импортирован
status: current             # current | legacy | deprecated
content_hash: 139d4d320b32b134
review_after: 2025-09-10    # дата источника + 6 месяцев, а не дата импорта + 6 месяцев
```

## Модель старения

1. **Двое часов, которые не смешиваются.** `source_updated` — собственная дата страницы,
   `ingested` — дата экспорта. Дата из zip никогда не используется как дата страницы: это
   выдавало бы старое содержимое за свежее.
2. **`review_after` считается от даты источника**, поэтому старая страница помечается сразу, а не
   получает новый полугодовой кредит доверия.
3. **Повторный импорт — это diff, а не перезапись.** Неизменённые тела остаются побайтово теми же
   (рукописные заметки выживают), изменённые перегенерируются, удалённые страницы становятся
   tombstone (`status: deprecated`), а не исчезают.
4. **`audit` строит очередь ревизии**, отсортированную по степени устаревания, с причиной по
   каждой статье и «сигналами» — количеством IP-адресов, версий, путей, URL, — которые
   показывают, насколько страница склонна устаревать.
5. **Правило для агента живёт в `../skill/SKILL.md`**: изменчивые факты из старой статьи либо
   проверяются вживую, либо явно датируются, но никогда не подаются как текущие.

## Файлы на диске, которые Confluence назвал не для файловой системы

- **Заголовки вложений — не имена файлов.** `image 21:0:24.png` допустим в Confluence и
  запрещён в Windows. Каждый компонент пути приводится к переносимому виду (запрещённые
  символы → `_`, хвостовые точки убираются, служебным именам вроде CON добавляется префикс,
  длина ограничивается) и при распаковке архива, *и* когда статья ссылается на вложение, —
  поэтому ссылка и файл совпадают.
- **Один файл на `id` страницы.** База накапливает файлы из нескольких импортов, и один и тот же
  `id` может оказаться в двух файлах (старый импорт с другим заголовком, экспорт, повторяющий
  `id`). Импорт удаляет устаревшего двойника и показывает это как `duplicates`; индекс держит
  одну строку на `id` и предупреждает об остатках вместо падения.
- **Пустые страницы пропускаются** («no content»): страница без тела остаётся в вики, но не в
  базе.
- Распаковка обходит ограничение Windows в 260 символов пути, а URL скачивания, оставленный
  сервером с пробелом, кодируется перед запросом.

## Тесты

```powershell
python engine\tests\run_tests.py
```

17 кейсов на синтетических экспортах и моке Confluence: разбор, удаление шума, макросы, таблицы,
идемпотентный повторный импорт, выживание рукописных пометок, изменённые и исчезнувшие страницы,
поиск, аудит, старый экспорт без метаданных `ajs-*`, windows-1251, REST-мок (Bearer и Basic,
пагинация, CQL, вложения), `--progress` на обоих путях, `inspect` и его коды ошибок, сужение
`--spaces`, переносимые имена файлов, дубликаты `id` и совпадение копии движка в скилле с этим
файлом.
