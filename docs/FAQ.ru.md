# FAQ

## Ссылка на статью открыла «Файл не найден»

Ссылка была относительной (`projects/a.md`). Приложение разрешает её от рабочего каталога сессии, а
база знаний лежит в `~/.dsh/kb`, вне его. Теперь результаты инструментов печатают абсолютный путь
`file=`; цитируйте его. Ответ, написанный до исправления, сохраняет битую ссылку — спросите ещё
раз, чтобы получить рабочую.

## Приложение не стартовало после сохранения логина

Хранилище секретов принимает ровно `<scope>/<id>`. Прежняя версия писала ключи из трёх сегментов
(`confluence-kb/<источник>/basic`), провайдер не мог загрузить файл, и приложение падало на старте.
1.0.0 держит одну запись на источник под `knowledge-base-tools/<id>`. Если в
`~/.dsh/.credentials.yaml` остался старый ключ, удалите записи `confluence-kb/…` и сохраните
учётные данные заново.

## Почему нельзя изменить базовый URL?

Источник уже загружался с него, и статьи хранят этот адрес. Правка заставила бы локальную базу
ссылаться на сервер, который её не отдавал. Удалите файлы базы, чтобы разблокировать поле, или
создайте новый источник для другого сервера. Источник, восстановленный из архива, остаётся
зафиксированным.

## Где лежит моя база знаний?

`%USERPROFILE%\.dsh\kb\<id>\`, где `<id>` — id источника; реестр —
`%USERPROFILE%\.dsh\kb\knowledge-sources.json`. Каталог источника по умолчанию отвечает и на
`KB_HOME`, если вы задали его для движка.

## Почему экспортированный архив такой большой?

В нём статьи, индекс и все вложения. Распакованный экспорт, использованный как вход импорта
(`raw/`), не включается. Реальная база на 1734 страницы занимала около 1 ГБ с вложениями.

## Почему число статей в экспорте отличается от страницы настроек?

Среди вложений бывают markdown-файлы; они едут в архиве, но статьями не являются. Теперь счётчик
их исключает, и числа совпадают.

## Можно ли восстановить базу, экспортированную до 1.0.0?

Да. Архивы со старым маркером `confluence-kb.json` / `dsh-confluence-kb-base` ещё принимаются
`unpack`; архив, записанный 1.0.0, использует `knowledge-base.json`.

## Почему встроенный браузер не логинится с кредами плагина?

Вкладка браузера — изолированная сессия Chromium со своими cookies, и она отвергает URL с логином
и паролем; Host не может подставить заголовки. Для страницы первоисточника используйте браузер по
умолчанию (Настройки → Общие → «Открыть ссылки на чат в»), где сессия уже есть.

## Почему Confluence Cloud не поддерживается?

Cloud использует другую авторизацию и другой REST-интерфейс. Плагин нацелен на Server и Data
Center; Cloud был бы отдельным адаптером.

## Почему второй импорт был отклонён?

Импорты идут по одному на источник. Дождитесь текущего или остановите его; другой источник может
импортироваться параллельно.

## Где хранятся учётные данные?

В хранилище секретов DSH (`%USERPROFILE%\.dsh\.credentials.yaml`), одна запись на источник, никогда
в базе, никогда в экспортированном архиве, никогда в git. Запуск передаёт их движку через
окружение.
