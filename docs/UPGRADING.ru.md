# Обновление

## С приватной сборки 2.x до 1.0.0

Имя пакета, префикс маршрутов, scope секретов, файл реестра и раскладка баз изменились, поэтому
**автоматической миграции нет**. Сама база не переписывается: переименование её каталога сохраняет
все статьи.

1. Остановите приложение и сделайте копию `%USERPROFILE%\.dsh\kb` и
   `%USERPROFILE%\.dsh\.credentials.yaml`.
2. Переименуйте каталог базы, например `~/.dsh/kb/confluence` → `~/.dsh/kb/<id>` (id, который
   будете использовать, например `confluence-fuzzy`). Именно переименование на том же томе, не
   копирование.
3. Установите скилл: скопируйте `skill/` в `%USERPROFILE%\.dsh\skills\knowledge-base\`.
4. Установите бандл `dsh-knowledge-base-1.0.0.tgz` (или подключите `plugin/` ссылкой для
   разработки) и убедитесь, что зависимость профиля и `dsh.profile.bundles` называют
   `@flumpfox/dsh-knowledge-base`.
5. Запустите приложение, откройте «Настройки → База знаний» и создайте источник с выбранным id,
   тем же базовым URL и пространствами. Страница возьмёт `~/.dsh/kb/<id>`, где теперь лежат старые
   статьи; число статей должно совпасть.
6. Введите учётные данные заново: 1.0.0 читает `knowledge-base-tools/<id>` и не смотрит на старую
   запись `confluence-kb-tools/...`. Сохранение не требует доступного сервера.
7. Не запускайте импорт, если сервер недоступен; проверяйте локальную базу:
   `kb.py --kb ~/.dsh/kb/<id> stats` и `kb.py --kb ~/.dsh/kb/<id> search "term"`.
8. Удалите старый каталог скилла и старый файл реестра, когда новый источник заработает.

Если сохранился экспорт базы до 1.0.0, он по-прежнему открывается: старый маркер
`confluence-kb.json` / `dsh-confluence-kb-base` принимается `unpack`.

## С более раннего релиза 1.x

Обновите репозиторий, выполните `npm test` и `npm run pack`, установите новый бандл и
перезапустите приложение, если менялись имя пакета или строка бандла. Базы и источники остаются на
месте.

## Откат

Перед обновлением сохраните предыдущий `.tgz` и bundle-снимок репозитория: приватная история
проекта использует для этого теги. Откат переустанавливает предыдущий бандл; каталог данных не
затрагивается, если не менялся формат (однажды это случилось — в 1.0.0, см. выше).
