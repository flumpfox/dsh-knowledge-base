# Разработка

Как работать над самим репозиторием: окружение, структура, тесты и циклы запуска на живом
профиле.

## Окружение

- DSH Desktop `0.2.2-rc.x`; Host-плагин работает внутри приложения, поэтому версии Electron/Node
  берутся из DSH (проверено: Electron 44.7, Node 24.21).
- Python 3 для движка. Плагин предпочитает runtime, встроенный в DSH, затем `python3`/`python`.
  `KB_PYTHON` переопределяет выбор для тестов и плагина.
- Node 22.5+ нужен инструментам (`node:sqlite`); приложение предоставляет его.
- Скрипты поддерживают Windows, macOS и Linux; проверенная платформа — Windows 10/11.

## Структура репозитория

| Путь | Что это |
|---|---|
| `engine/kb.py` | движок: импорт, fetch, поиск, audit, экспорт/импорт базы |
| `engine/tests/` | фикстуры, мок Confluence, сквозные кейсы движка |
| `plugin/` | бандл DSH: инструменты, маршруты, страница настроек, локали |
| `skill/` | скилл, устанавливаемый в `~/.dsh/skills/knowledge-base` |
| `tools/` | скрипты репозитория: тесты, сборка, проверка секретов |
| `docs/` | публичная документация; в `private/` — документы только для мейнтейнера |
| `dist/` | собранные пакеты (игнорируется) |

## Тесты

```powershell
npm test                  # кейсы движка и набор плагина
npm run test:engine       # только движок
npm run test:plugin       # только плагин
npm run pack              # сборка dist/dsh-knowledge-base-<версия>.tgz
npm run check-secrets     # проверка отслеживаемых файлов и пакета
```

Тесты плагина запускают настоящий движок и мок, поэтому им нужен Python. Они изолируются через
`KB_DIR` (временный домашний каталог) и никогда не трогают `~/.dsh/kb`; тесты движка используют
`KB_HOME` или явный `--kb`.

## Запуск на живом профиле

1. В `~/.dsh/profiles/<profile>/package.json` держите зависимость-ссылку на `plugin/` и добавьте
   имя пакета в `dsh.profile.bundles`; выполните `pnpm install` в профиле.
2. Переключайте бандл через `set_bundle` после правок Host; связанный модуль перезагружается без
   перезапуска. Клиентские изменения требуют обновления страницы (в собранном приложении нет
   горячей клавиши; перезапуск или DevTools).
3. Переименование пакета или смена id строки требуют перезапуска приложения: загрузчик читает
   профиль при старте.

Данные лежат вне репозитория: `KB_DIR` (по умолчанию `~/.dsh/kb`) хранит
`knowledge-sources.json`, по каталогу на источник и `exports/`.

## Отладка

- В лог Host попадают предупреждения плагина, включая запасной путь `dsh-tools` и ошибки
  регистрации маршрутов.
- `GET /x-knowledge-base/sources` и `/sources/<id>/state` описывают реестр и источник;
  `lastRejectedWrite` объясняет отклонённую cross-origin запись.
- У задачи импорта есть последние 40 строк движка; `kb.py --version` показывает версию движка, а
  `kb.py inspect --zip` проверяет экспорт, не трогая базу.
- Каталог базы можно проверить напрямую: `kb.py --kb <dir> stats` и
  `kb.py --kb <dir> search "term"`.

## Цикл релиза

1. Поднять версию в `plugin/package.json`, обновить оба changelog-файла.
2. `npm test` и `npm run check-secrets` должны быть зелёными.
3. Поставить тег `vX.Y.Z` в приватном репозитории; workflow релиза соберёт `.tgz`, `skill.zip` и
   `SHA256SUMS` и прикрепит их к GitHub Release.
4. Перед анонсом установить релиз на чистый профиль.

## Восстановление на новой машине

Установить DSH, клонировать репозиторий, положить `skill/` в `~/.dsh/skills/knowledge-base`,
установить бандл, затем создать источник и ввести учётные данные. Подробности и переход с прежних
версий: [docs/UPGRADING.ru.md](UPGRADING.ru.md).
